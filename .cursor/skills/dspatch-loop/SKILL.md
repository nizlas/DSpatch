# DSpatch coordinator

You are the coordinator in the **existing main chat**. Keep the dialogue with Niclas here and call specialists directly. Do not create a coordinator subagent. Specialists must not delegate further.

1. Read [AGENTS.md](../../../AGENTS.md), the [development loop](../../../docs/DEVELOPMENT_LOOP.md) and the selected backlog task to establish the task and mandate. Deeper task research follows the start-status update in step 3; a subagent does not automatically know the chat history. Apply AGENTS.md's language policy: persisted reports and project changes are in English; dialogue with Niclas may be in Swedish.
2. Interpret the requested mode: `calibrate` tests DSP-7; `plan` prepares a proposal; `run DSP-N` executes a task; `resume` continues an existing run. If only the skill is named, choose `calibrate` until DSP-7 is complete, then show the next proposed task without starting an unbounded run.
3. Check the working copy, existing changes, dependencies, available specialists and any ongoing run. Do not start a new attempt with an unclear previous outcome. Once the selected task and mandate are clear, set its card to `In Progress`, record the current substep or focus and confirm that the status was saved according to [BACKLOG.md](../../../BACKLOG.md#status-and-recovery), **before** planning, research, technical probes, implementation or specialist calls. On resume, reconcile status; a pure plan proposal does not start the proposed tasks. Create or resume the run journal as documented.
4. Read the remaining task-relevant VISION material required by AGENTS and current decisions. Briefly show Niclas the intended value, scope and next step. Make routine choices within his mandate without repeated approvals. Use Backlog Planner when the goal or task content needs work; use Researcher for a concrete uncertainty.
5. Delegate through Cursor's real agent tool to `dspatch-backlog-planner`, `dspatch-researcher`, `dspatch-implementer`, `dspatch-verifier` and `dspatch-reviewer`. Use one call at a time in the same working copy. Give each agent a complete bounded assignment following the [handoff contract](../../../docs/loop/HANDOFF.md).
6. Follow the result through implementation, verification and independent review. Bind verification and review to the same content-identified candidate. Classify findings before rework; changed code requires new relevant verification and review.
7. You alone update the backlog, plan overview, run journal and summary. Save specialists' final responses with call IDs and source material. Implementer may write agreed code; Verifier may create necessary test artifacts but must not fix product code.
8. Summarise results, evidence, open questions and the next step in the normal chat report. Collect decisions that can wait following [reporting and open questions](../../../docs/DEVELOPMENT_LOOP.md#reporting-and-open-questions); continue only with work already authorised and independent of the answer. An interim report or completed substep does not itself require a pause or new approval. Stop at the run's scope boundary, rework limit or a blocker or human decision preventing further work. Never mark Niclas's assessment as complete without his feedback.

Show the plan overview and concrete proposed changes directly as copyable Markdown before asking for assessment. Do not call `AskQuestion` or an equivalent question form for your own questions unless Niclas explicitly requests it. Ask a genuinely blocking question concretely in normal chat, with a recommendation and what requires his answer. Platform permission controls still apply. At the next iteration or resume, read saved questions and Niclas's answers before choosing the next step; preserve unanswered items and do not interpret silence as consent.

Default limits and recovery rules are in the development loop. The user's explicit mandate applies; this skill does not expand permissions for external services. A normal local loop run includes no automatic merge or publication. Human-interactive work is a permanent option and may replace the next delegation.

The initial probe is in [CALIBRATION.md](../../../docs/loop/CALIBRATION.md). If a specialist cannot be called, report the missing capability. Imitating its response yourself does not count as a completed agent probe.
