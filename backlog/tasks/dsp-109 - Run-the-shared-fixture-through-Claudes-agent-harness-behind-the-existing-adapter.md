## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Niclas (21 Oct 2026) wants DSpatch work to run through Claude's actual agent harness, not only Claude models through Cursor (Q2, confirmed), with a direct Claude Agent SDK path as the diagnostic and reference baseline before AHP is compared. Claude models already run through Cursor; this card adds Claude's harness (tool set, permission rules and modes, session IDs DSpatch chooses) behind the existing AgentAdapter, exercised from the command line on the existing synthetic fixture at home on Windows. Behaviour reach: a new provider adapter and probe scenarios only; no role, node, graph or Maestro rule changes. Plan baseline: run 20261021-133119-plan-rt, report 003 (Reviewer ACCEPT in report 004), amended by Niclas's answers of 21 Oct 2026.

Scope:
- app/src/adapter/claude-agent-sdk-adapter.ts implementing AgentAdapter (main process only, excluded from the renderer tsconfig like the Cursor adapter). ProviderId gains 'claude'; adapter id 'claude-agent-sdk' (Anthropic's branding rules do not permit presenting it as "Claude Code"). Pin @anthropic-ai/claude-agent-sdk exactly.
- Fixture configuration, recorded in every run record: tools ['Read','Glob','Grep','Edit'] (availability); allowedTools ['Read(/**)','Edit(/src/**)'] (pre-approval scoped to the session's working directory; single-slash rules anchor at cwd per the SDK permissions page; no bare Read, Glob or Grep, so dontAsk denies reads outside the fixture); permissionMode 'dontAsk' (documented: a call that would prompt is denied and canUseTool is never called, so nothing hangs on an unanswered prompt); settingSources []; exactly one root (more than one is refused with a clear error). bypassPermissions, acceptEdits and auto are not used. Whether Glob and Grep inside cwd are covered by the Read rule is unverified; a denial is read from permission_denials and reported, not fixed by widening rules.
- Capability report: approvals 'unsupported' (canUseTool is not wired to anything that can answer); usageReporting 'unknown' unless observed otherwise; no containment claim (types.ts "Roots, not permissions": for Claude, cwd scopes permission rules, which is not containment).
- Authentication (Niclas, Q1 as clarified 21 Oct 2026): subscription-backed use of the SDK through Niclas's Claude Max login is not assumed to be authorized for DSpatch's own third-party Agent SDK integration; it remains an unresolved terms/authorization question until Anthropic's permission or applicable documentation establishes that it is allowed. Claude Code authentication tokens are not reused or extracted to get around this. API-key billing is a separate option behind an explicit approval gate: no API charges without Niclas's approval. Claude Code's documented precedence puts ANTHROPIC_AUTH_TOKEN, ANTHROPIC_API_KEY (always used in non-interactive mode when present) and apiKeyHelper above CLAUDE_CODE_OAUTH_TOKEN and the /login subscription credential, so the live scenarios refuse to start while any of ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN, CLAUDE_CODE_USE_BEDROCK/VERTEX/FOUNDRY is set in their environment, unless an explicit, recorded API-key approval is given for that run, and record which was found. Never fall back to paid API usage silently.
- experiment-work.ts: openSession, makeRecorder and readUsage generalised to AgentAdapter with a provider choice; Cursor-only calls (providerMessageTypes, streamPumpFinished) made conditional. Two new provider-generic subcommands: cancel-reply (read-only prompt: read every file and write a long per-file explanation in the reply; cancel after the first assistant text delta, waited for specifically, not Recorder.firstActivity(), which also resolves on a tool call) and two-turn (turn one plants a nonce generated by the script; turn two, a second send in the same adapter instance, asks for it back).
- Fix the stale comment in app/src/adapter/agent-adapter.ts:29-30.
- Run records also state where provider state was written (documented as ~/.claude/projects/<encoded-cwd>/*.jsonl unless CLAUDE_CONFIG_DIR is set; observe, do not assume) and what the init message showed about managed policy.
- Remote-ready separation, not remote work: the adapter stays in the main process behind AgentAdapter and adds no assumption that the renderer and the execution share a machine or a filesystem (see DSP-111).

Exclusions: UI or chat provider selection; connectedTargets; TARGET_CAPABILITIES rows (unchanged unless an observation is recorded beside a change, as DSP-76 #2 requires); approvals UI; more than one root; AgentAdapter.resume across processes (not covered, deferred); Electron packaging; Linux (later, in a separate clone); remote execution; AHP; Copilot; content exclusion; DSpatch persistence changes; any change to CursorSdkAdapter; any Claude or Anthropic credential on the work computer.

Dependencies: none on backlog cards (DSP-1/4/71/72 reused, not required). No Copilot account is needed. The live criteria (#3-#7) need the authentication path established first (#3).
