## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in DSP-165's Windows verification (3 November 2026): after the client that started the local standalone host ended, its DevTools port stayed bound until the host ended. Suspected: the host inherits a listening socket handle when it is started. Only the debugging port's behaviour has been observed.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The cause is established by reproduction, told apart from a lingering client process and from a debugger the host starts through inherited arguments or environment
- [ ] #2 The host is started so that it holds none of the client's debugging resources, by a bounded change in the process start
- [ ] #3 Verified on Windows with an isolated profile: the client's debug port is free once the client has ended while the host lives, work goes on, the client reopens on the same host with no second start and no lost history, and the host's own port, ownership and logging still work
- [ ] #4 A focused regression test where it is practical
