# DSpatch 0.1.12

A Linux-only pre-release with the changes from Niclas's evaluation of 0.1.11: step explanations apart from the discussion, clearer profiles, one code place per walk step, references that lead somewhere, and reviews as independent instances. No Windows installer or Windows host package is published; the Windows work (DSP-182) is still open.

## Step explanations and the discussion (DSP-184)

- Choosing a profile, Regenerate, *Tell me more*, *Explain more simply* and *Explain this* in **Step** now only change the step's explanation. They add nothing to **Discussion** and do not wait for, or hold up, a question you are asking there.
- Each profile keeps its own explanations per review, walk and step, with **Earlier/Later** to go back through them. The walk's own text is always the first entry for the profile it was written in. Switching back to a profile shows its saved text without a new call.
- Discussion keeps your conversation. A profile switch adds nothing to it and does not change its style. A question about the step you are reading takes that explanation along as context, without copying it into the chat. Automatic profile entries made by 0.1.11 and earlier are hidden in Discussion but not deleted.
- Failed explanations wait for **Try again**; nothing is resent on its own.
- **Profiles:** Essentials gives the purpose and main course in about two plain sentences. Standard explains how the parts connect and which consequences matter, for a developer who does not know this code. Teacher builds the concepts needed to judge the code, with examples where they help. All three are asked to add understanding beyond what the code and its comments already say, to read the relevant code before writing, and to keep what the code shows apart from interpretation.
- The Step panel has the same layout in every profile, with the place navigation above the explanation. *What it asks for* and the instruction text are no longer shown in the review view; the instructions and their version are kept with each stored explanation.

## Walks (DSP-185)

- Newly prepared walks normally show **one code place per step**, each with its own explanation. Several places in one step only when comparing them helps, with the reason shown. Walks prepared before keep opening unchanged.
- A walk follows important new or changed functions into their implementation as steps of their own, instead of only naming them.
- **Each code place has its own pane**, also when several are in the same file, and keeps its position when you step back and forth.
- References in explanations lead to the matching walk step (also in another walk of the review), or open the code with the lines marked, with **Back** to where you were. A reference to code outside the diff says so, and one that cannot be resolved is shown as plain text.

## Reviews as instances (DSP-186)

- **Start a new review** always makes a new, empty review, even for commits you have reviewed before. Each review keeps its own walks, explanations, discussion and marks.
- **Close review** keeps a review for reopening. **Delete…** removes that review and only its own material. Several reviews of the same commits can be open at once.
- When walks were prepared with earlier settings, the review says so; nothing is regenerated by itself.
- Reviews made by earlier versions open as before. The first time 0.1.12 writes review data, it copies the existing review records to `~/.config/DSpatch/reviews/backup-<time>-pre-review-ids/` once.

## Install or upgrade

Install `dspatch_0.1.12_amd64.deb` on Debian or Ubuntu x64 (`sudo apt install ./dspatch_0.1.12_amd64.deb`). Installing over an earlier version keeps `~/.config/DSpatch`.

The host's contract changed in this release, so a 0.1.12 client cannot use a host started by an earlier version. If one is still running when you start 0.1.12, a dialog *Another DSpatch host is running here* appears before any window: choose **Stop it and continue**. A host on a machine you connect to over SSH is replaced from this release's host package when you connect.

`dspatch-host-0.1.12-<commit>-linux-x64.tar.gz`, `host-manifest.json` and `SHA256SUMS` are published with this release.

## Verification

Checked before and after publication (details in DSP-187): the test groups and `linux-verify`; client and host with one build identity and no Windows files; the walk, profile, thread, dock, zoom and review-instance window trials; an upgrade from 0.1.11 with a running host; the published files against `SHA256SUMS` and the installed smoke test. All with isolated profiles, neutral throwaway projects and the simulated provider.

Not established:

- What a real model writes with the new instructions on real code. The simulated provider shows the interface and that the instructions reach the prompts. An additional check had model-written answers to DSpatch's own prompts on a synthetic example judged for understanding, outside DSpatch's providers; it is not evidence of how your provider behaves.
- Windows, other distributions than Ubuntu and Debian, and arm64.
