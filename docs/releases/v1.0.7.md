# DSpatch 1.0.7

An ordinary release for **Linux x64** and **Windows x64**, and the new latest release. It simplifies the generic agent network with model classes and review routes chosen per visit, and keeps a step's visits apart.

## Model classes and agent execution graphs (DSP-221 to DSP-224)

- **Terms.** DSpatch describes its workflows as agent execution graphs; agent loops are a special case. The UI says graph editor, graph run and Run log.
- **Model classes.** A step can ask for a model class (small, medium or large) instead of a model. **Model classes…** in the graph editor sets, per agent, which model each class runs, from the chat's own model list, or *Use chat model*. A change applies from the next run, never to a run in progress, and the agent is never switched.
- **Choices per visit.** A graph can let a step decide, per visit, choices such as the model class and the review route, independently of each other and of its outcome. Edges can be taken only when a choice has a value, so one node can be followed by different checks. Choices travel with the work through revisits and rework, and the run log records each one, who made it and why.
- **Generic agent network.** One node per role: Implementer, Researcher, Reviewer and Skeptic are no longer split into size variants (35 → 31 nodes). Tech Lead's dispatch chooses the class and the review route. Standard goes through QA, a review and a challenge; thorough goes through design QA, a design review and a full challenge. Escalations are kept.

## A step's visits (DSP-224, DSP-225)

- **On the node.** While a run walks, a node whose class is chosen per visit carries a tag with the class of the visit running now, or of the latest visit afterwards: *Small*, *Medium* or *Large*, or *S*, *M* or *L* when zoomed out. The line below says *now: visit 2 · model* or *latest: visit 2 · model*. Before its first visit the node says the class is chosen per visit. The hover shows the visit, class, model, provider and why, and which chat model *Use chat model* resolved to.
- **Output per visit.** The node panel lists the latest visit first, with its class and model, and earlier visits below. The step output window opens on the latest visit and moves back to earlier visits and forward again in the same window. A visit that starts while you read an earlier one is offered, not switched to.
- **Agent context.** Each visit says whether its agent continued the step's earlier session, with the earlier conversation in context, or ran in a new one. Showing visits apart does not make a revisit an independent review.

## Install

- **Linux (Debian/Ubuntu x64):** `dspatch_1.0.7_amd64.deb`. Check it against `SHA256SUMS` and install it with `sudo apt install ./dspatch_1.0.7_amd64.deb`. It carries both host packages, so it can install a host on a Linux or a Windows computer.
- **Windows (x64):** `DSpatch-Setup-1.0.7.exe`, a per-user installer. It is not signed; see [INSTALL.md](../INSTALL.md#windows).
- **After an upgrade,** a host started by the earlier version keeps running. The window reads *Restart needed to finish updating*, and **Restart host** starts this version's host with the data kept.

## Known limits

**Tried by agents, all simulated:**
- Targeted tests, among them two visits of one node (small, then large) through the run engine with simulated Copilot and Claude adapters.
- The type check and the build.
- A window trial in an isolated profile with simulated replies, covering the class tag during a visit, the visit list and an open window staying on its visit.
- Recorded runs shown in Run view, normal and zoomed out.

**Not yet tried:**
- Any real provider.
- Windows.
- The rest of the window trial for this release: following a visit, zoomed out during a live run, and after a restart.

**Session behaviour, as observed:** a revisit with the same model continues the step's session on every agent. With another model, Claude switches the model in the same session, and the other agents open a new session.

**Editing:** choices, `sets` and `whenChosen` are edited in the graph file. The editor shows them but does not edit them.
