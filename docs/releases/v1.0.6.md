# DSpatch 1.0.6

An ordinary release for **Linux x64** and **Windows x64**, and the new latest release. It adds a generic multi-agent loop that comes with DSpatch.

## A generic agent network for any project (DSP-220)

- **Generic agent network** is a fifth bundled loop. Choose it in the loop editor's **Loop** list, beside the other bundled loops, in any project. Nothing is copied into the project and no DSpatch checkout is needed. Choosing or opening it starts nothing, and it is never preselected: a workspace keeps the loop it last chose.
- **Roles and flow.** An Executive takes the mandate; a Tech Lead plans, a Planner and a small Reviewer make the plan ready, and Backlog records it. Tech Lead dispatches each slice to an Implementer, Explorer or Researcher (small, medium or large), a Data Curator, Infrastructure or an Experiment Analyst, or escalates to a senior Tech Lead. QA checks the work, Reviewers and Skeptics challenge it, Tech Lead accepts or sends it back, and the Executive continues with the next slice or wraps up; a Documenter, Tech Lead and the Executive deliver the report. A failure routes back to dispatch or planning; a spent limit routes to wrap-up.
- **Provider-agnostic.** It runs with the agent and model chosen in the chat; requirements are checked against that agent's integration.
- **The project's instructions come from the open project**, through the context every chat loop run receives: the first step is told which instruction files are present, such as `AGENTS.md`, and every step works in the project's folder.
- The arranged layout prefers a plainer layering when that has fewer crossings in the main flow and no worse label placement.

## Install

- **Linux (Debian/Ubuntu x64):** `dspatch_1.0.6_amd64.deb`. Check it against `SHA256SUMS` and install with `sudo apt install ./dspatch_1.0.6_amd64.deb`. It carries both host packages, so it can install a host on a Linux or a Windows computer.
- **Windows (x64):** `DSpatch-Setup-1.0.6.exe`, a per-user installer. It is not signed; see [INSTALL.md](../INSTALL.md#windows).
- After an upgrade, a host started by the earlier version keeps running; the window reads *Restart needed to finish updating*, and **Restart host** starts this version's host with the data kept. For a Windows host used from Linux, Connect installs this version's host there.

## Known limits

Tried by agents: targeted tests, among them the generic network run from a copy outside the repository through simulated Cursor, Claude and Copilot adapters; the type check; the packaged Linux build, headless with an isolated profile and a separate repository, where the loop is listed, opens with its roles from the installed files and works in that repository.

Not yet tried: the generic network with a real provider; on Windows.

What the run engine does not provide for this loop, carried by instructions or by ending the run instead: the small, medium and large variants share the chat's model; a job that needs human authorization ends the run with a report rather than pausing it; slices run one at a time; the carry-forward ledger in each reply is not verified; limits bound routing and are not a hard cap. See `docs/loop/graphs/generic-agent-network.README.md`.
