# DSpatch 1.0.5

An ordinary release for **Linux x64** and **Windows x64**, and the new latest release. It makes DSpatch's own loops provider-agnostic.

## Loops run with the agent chosen in the chat

- **One choice of agent and model (DSP-218).** The agent (Cursor, Claude or Copilot) and its model are chosen in the chat, for a loop started from the chat and for the loop editor's Run alike. Beside Run, the loop editor shows read-only what the run uses, for example *Runs with Copilot · claude-opus-5.5*, and says when steps set their own model; during a run it names the model of a step that runs its own. The *Target framework* chooser is gone from the toolbar.
- **The same loop with any of the three (DSP-219).** A loop's `target` is now an export format for agent files used outside DSpatch, under the graph's *Advanced: export format for agent files*. It no longer decides whether DSpatch can open, choose, validate or run a loop, and roles are read for their common instructions whichever agent runs them. Loops saved before keep their target and need no change; a loop whose roles have no form for its target, refused before, now runs.
- **Requirements are answered by the agent that runs the loop.** Each step's requirements show as *enforced*, *instruction only*, *not supported* or *not established*, in the editor and when a run starts. A requirement the agent cannot meet refuses the run, naming the step, the requirement and the limit; DSpatch never switches agent or model on its own. The answers that are not *enforced* go on the run's record. Whether the working folders are measured follows the agent too.
- **DSpatch's own parallel branches are not the agent delegating.** A step's ban on starting agents of its own never stops a loop's fan-out. With Cursor the branches run one after another, and the editor says so.

## Install

- **Linux (Debian/Ubuntu x64):** `dspatch_1.0.5_amd64.deb`. Check it against `SHA256SUMS` and install with `sudo apt install ./dspatch_1.0.5_amd64.deb`. It carries both host packages, so it can install a host on a Linux or a Windows computer.
- **Windows (x64):** `DSpatch-Setup-1.0.5.exe`, a per-user installer. It is not signed; see [INSTALL.md](../INSTALL.md#windows).
- After an upgrade, a host started by the earlier version keeps running; the window reads *Restart needed to finish updating*, and **Restart host** starts this version's host with the data kept. For a Windows host used from Linux, Connect installs this version's host there.

## Known limits

Tried by agents: targeted tests, among them the bundled chat loop run with Cursor, Claude and Copilot through simulated adapters and with Copilot's real runtime behind a local stand-in model; the type check; the changed editor parts seen in this checkout's build, headless with an isolated profile.

Not yet tried:

- any of the three with a real account in a loop since these changes;
- the model line during a running loop on a real screen.

What each agent does about a requirement is read from documentation and offline checks unless stated: with Cursor, `no-file-writes`, `background-execution` and `no-subagent-delegation` hold by instruction only and `tool-restriction` is not established; with Claude and Copilot, `no-file-writes` and `background-execution` hold by instruction only and the rest are enforced by the options DSpatch passes.
