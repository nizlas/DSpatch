# DSpatch 1.0.0

DSpatch 1.0.0 is the first ordinary release of DSpatch, for **Linux x64** (Debian and Ubuntu). It is the functionality of 0.1.25 under a 1.0 version: nothing in DSpatch's behaviour changes from 0.1.25. No Windows installer or Windows host package is published; on Windows, DSpatch is run from the repository.

## What DSpatch offers

DSpatch is a desktop workspace for agent-assisted development and code review.

- **Develop in conversation.**
  - Talk with an agent about a project.
  - Ask for changes, and have the agent build and test them.
  - The agent is Claude or Copilot, through the provider's own sign-in.
- **Delegate through loops.**
  - Choose or edit an agent loop and follow its steps.
  - Steer the work, and decide when the next step starts.
- **Review a change.**
  - Open a full diff between two Git revisions, with expandable context.
  - Ask about selected code.
  - Let an agent prepare **code walks**, which explain a change as connected steps, in three explanation profiles.
  - Delegate chosen parts of the review to an agent; the decision stays with you.
  - Review works for changes made in any editor, not only in DSpatch.
- **Work on another machine.**
  - Keep the window on your computer while the repository, agents and tools run on a host over SSH.
  - DSpatch transfers and checks the matching host package itself.

The [README](https://github.com/nizlas/DSpatch#readme) and the [tutorial](https://github.com/nizlas/DSpatch/blob/main/TUTORIAL.md) describe these in more detail.

## Install

Download `dspatch_1.0.0_amd64.deb` and `SHA256SUMS` from this release, check the package and install it:

```bash
gh release download v1.0.0 --repo nizlas/DSpatch --pattern 'dspatch_1.0.0_amd64.deb' --pattern 'SHA256SUMS'
sha256sum --check --ignore-missing SHA256SUMS
sudo apt install ./dspatch_1.0.0_amd64.deb
```

Without the GitHub CLI, download the two files from **Assets** below, then run the last two commands in the folder you saved them to.

Start **DSpatch** from the application menu. The package includes the application runtime and its sandbox setup. For agent features, you need an account with the chosen provider. Git is needed on the machine that holds the repositories.

## Upgrade

Install the new package over the old one with the same `apt install` command. Your conversations, reviews, projects, agent choice, zoom and review preferences in `~/.config/DSpatch` are kept, and so are the loops in your projects.

1.0.0 changes no host method, so it works with a host started by 0.1.15 to 0.1.25:

- **A host from 0.1.15 to 0.1.25 still running.** A window that was closed leaves its host running, and DSpatch keeps it. At start the window says a restart is needed and offers **Restart host**. Press it: DSpatch ends the old host, starts this version's, and continues with the same project.
- **A host started by 0.1.14 or earlier.** It cannot serve this window. At start DSpatch asks **Stop it and continue** or **Quit DSpatch**.

**Help > About DSpatch** shows which version the app is and which version the running host is. After **Restart host**, both say 1.0.0.

On a remote machine over SSH, DSpatch installs the 1.0.0 host when it connects. The package carries that host, so nothing is downloaded for it.

`dspatch-host-1.0.0-<commit>-linux-x64.tar.gz`, `host-manifest.json` and `SHA256SUMS` are published with this release.

## Known limitations

- **Platforms.**
  - Only Linux x64 is published, and it is tried on Ubuntu and Debian.
  - The following are not established: other distributions, arm64, Wayland, and GNOME's and KDE's own docks. The trials ran on X11.
  - Windows has no maintained installer; run DSpatch from the repository there.
- **Agents act on your project.** Agents in development chat and loops can change files and run commands.
- **Content exclusion is incomplete.**
  - Copilot's tool hooks run on the host, but they do not filter everything DSpatch sends: selected code and diffs in a prompt are outside them.
  - Read the [content-exclusion contract](https://github.com/nizlas/DSpatch/blob/main/docs/DSPATCH_CONTENT_EXCLUSION_CONTRACT.md) before using restricted material.
- **Claude support** has provider-specific conditions and an open approval question about distribution; see the [installation notes](https://github.com/nizlas/DSpatch/blob/main/docs/INSTALL.md#why-support-is-fetched-and-what-the-terms-say). A successful sign-in does not settle it.
- **Review by an agent.** The trials check how delegation is recorded and bounded, not how good a real model's review or code walk is. That depends on the model and on your code.
- **One client at a time** works with a host. A second window hands over unless work is running.

## Verification

Checked before publication; details are in DSP-205.

- **The published release in clean containers:**
  - every published file downloads;
  - the `.deb` matches `SHA256SUMS`;
  - the `.deb` installs without Node or npm on the machine;
  - **Remote Session** over SSH installs the host the client carries, without asking GitHub;
  - the host runs exactly this build;
  - a Copilot turn runs on that host.
- **An upgrade from 0.1.25**, in one container:
  - **Before the upgrade, 0.1.25 makes:**
    - a conversation with a turn;
    - a review with an agent's delegated result;
    - an agent choice and a saved zoom;
    - review preferences;
    - a loop of the person's own in the project.
  - **After installing 1.0.0 over it:**
    - the window offers **Restart host**;
    - Restart host replaces the 0.1.25 host;
    - all of the above is as it was, after Restart host and again after a restart of DSpatch;
    - **About DSpatch** names 1.0.0 for the app and for the running host, both times.
- **Simulated provider.** The agent turns in these trials come from a simulated provider; no model account is reached.
