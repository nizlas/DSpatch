# DSpatch 0.1.17

A Linux-only pre-release that gives the three explanation profiles their own pedagogical responsibility (DSP-192) and removes one line from the run view. No Windows installer or Windows host package is published; the Windows work (DSP-182) is still open.

## The profiles say what they are for (DSP-192)

- **The reference first.** `docs/CODE_WALK_UNDERSTANDING_AND_PROFILES.md` version 1.1 defines each profile's responsibility: Essentials gives an experienced developer an accurate main picture quickly, at a higher level of abstraction, by meaningful selection rather than by packing Standard's details into fewer sentences; Standard keeps its direction and behaviour and is the comparison point; Teacher builds the understanding the reasoning presupposes, chosen for the step and using what the walk has already established, not Standard plus more facts. All three are true to the same code, the review's findings stay in the review's state, and length is a consequence. A background-worker example shows the three readings side by side.
- **The instructions follow, version 8.** The Essentials and Teacher readers are rewritten from the reference; the shared rules say the prepared text and earlier answers are material and not a list of what must be said; *Show more* and *New response* continue for the same reader rather than inventory what the first part left out; Standard's reader is unchanged word for word. Walks and explanations saved by earlier versions are kept as they are and not regenerated; the *earlier version of the instructions* notice on them is the one from 0.1.15.
- **The loop's reviewer judges the help, not the amount.** It does not ask Essentials for the mechanics it left out unless their absence misleads, and does not ask Teacher for more detail to be longer; an omission that misleads is a finding in any profile. The writer's and reviewer's role texts say the same, and the writer's prompt no longer tells it both to name places by path and line and to name functions in the prose.
- **One line gone from the run view.** *The run goes on; what the agent reports appears here as it comes* no longer shows under the liveness line; nothing replaces it. The rest of the view is as in 0.1.16.

The comparison that went with this change (the same locked walk plan, revision and steps in all three profiles, through the loop writer's prompt and through a profile alternative made after the walk, plus the Essentials prompt of version 7 for the before-picture) is kept with its judgment in `docs/evaluations/dsp-192/`. It was answered by a stand-in model outside DSpatch's providers, and says nothing about what a real provider does with the same prompts.

## Install or upgrade

Install `dspatch_0.1.17_amd64.deb` on Debian or Ubuntu x64 (`sudo apt install ./dspatch_0.1.17_amd64.deb`). Installing over an earlier version keeps `~/.config/DSpatch`.

0.1.17 changes no host method, so its host contract is 0.1.15's and 0.1.16's. A host that 0.1.15 or 0.1.16 started and that a closed window left running is kept: at start DSpatch says a restart is needed to finish updating and offers **Restart host**; press it before preparing walks, since walks are prepared on the host with the host's instructions. A host that 0.1.14 or earlier started cannot serve this window: at start DSpatch asks **Stop it and continue** or **Quit DSpatch**, and this release's host then starts.

`dspatch-host-0.1.17-<commit>-linux-x64.tar.gz`, `host-manifest.json` and `SHA256SUMS` are published with this release.
