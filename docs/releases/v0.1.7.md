# DSpatch 0.1.7

## The host's status, said plainly

- The status line in every window reads **On this computer** while this computer's host is this build, with *End host* as before. Commit ids and build digests have left the line; they are in its tooltip and the logs.
- After an installed update the window may still be attached to the older host it left running. The line then reads **Restart needed to finish updating**, with a **Restart host** button: it ends the older host, starts this version's and reconnects the window, which is what *End host* already did. A different build of the same version, as in development, reads *The host is another build* and is not called an update.
- A remote connection still says which machine: *On <machine>*.

## Zoom with Control and the wheel

- Hold Ctrl and roll the wheel away from you to enlarge the window under the pointer, towards you to reduce it: one of the zoom keys' steps per notch, between the same bounds, remembered the same way. A high-resolution wheel's partial events add up to one step per ordinary notch. The gesture scrolls nothing at the same time; a plain wheel scrolls as before.
- The docked review discussion zooms with its review window; in its own window it keeps its own level, which docking does not change.

## The review discussion reads more easily

- More line height and space between paragraphs, list items, questions and answers; a readable line length in wide windows; quieter inline code; code blocks that scroll on their own; the answer's actions in one quiet row. The answers' content is unchanged.

## The docked discussion is drawn on Linux

- On Linux the review discussion docked in a code window was a frozen picture: Electron 44.0–44.7 leave a view hidden once it has been moved into another window, so it painted nothing new and took no clicks or keys. DSpatch now runs Electron 44.9.3, which has the fix (electron/electron#54626). This covers docking straight from one review window to another (A → B) as well.

## A resource governor, observing by default

- While a loop runs, the host reads the machine's pressure every 5 s on Linux: memory, disk and CPU stall (`/proc/pressure`), available memory, swap traffic and, without PSI, the load per CPU. It names a health (GREEN, YELLOW, RED, or UNKNOWN when a signal could not be read) and records each change, with its reasons and time, in the run's journal and the host's log, and the mode and health each step started under.
- **Observe is the default: it records and limits nothing.** `enforce`, chosen with `DSPATCH_RESOURCE_GOVERNOR=enforce` or `resource-governor.json` in DSpatch's data folder, holds the start of a new loop step under sustained pressure; commands a provider already runs are never paused or slowed. See docs/INSTALL.md.
- This gives records to find out what makes a machine slow during a run. It is not a fix for the slowness seen in an earlier loop run on Linux, whose cause is not established.

## Loop runs and the connection

- A Stop that arrives while a step is still reading the project's folders now ends the step before the agent is started; before, the agent could be started after the Stop.
- Unticking *Use loop* while the connection to the host is away no longer shows the run as stopped when the stop did not reach the host: the box comes back on and the window says the stop was not delivered.
- The host's log notes when its process was held for several seconds (`this process was held for N ms`) and the run id when a loop starts, for finding the cause of a disconnect.

## Linux download

Install `dspatch_0.1.7_amd64.deb` on Debian or Ubuntu x64. No separate Node, npm or host-package installation is required. The matching standalone host archive, its manifest and `SHA256SUMS` are also published. No Windows installer and no Windows host package are in this release.
