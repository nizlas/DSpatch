# DSpatch 0.1.4

## Unified local and remote host

- Local and remote clients use the same standalone host and authenticated loopback protocol. SSH provides the tunnel to another machine.
- Closing the desktop client leaves started work on the host. Reopening attaches to the same work and history without sending the assignment again.
- One user data folder has one host owner. Another client replaces the connection rather than restarting the host. Incompatible running hosts require an explicit stop decision.
- Workspace and workspace-less conversations preserve their active turn during reattachment.
- Local recovery discovers a restarted host's new endpoint without replaying pending work. A missing replacement leads to an explicit recovery choice, not an automatic new assignment.
- The Linux Debian package includes the matching Linux standalone host archive and manifest. Local startup and SSH installation use that verified bundle without a separate host-package download.

## Linux download

Install `dspatch_0.1.4_amd64.deb` on Debian or Ubuntu x64. No separate Node, npm or host-package installation is required. Provider preparation and sign-in still take place where the work runs. A matching standalone host archive and checksums are also published for inspection or managed deployment.

No system service or login-time startup is installed. No Windows installer and no Windows host package are included in this release, so a v0.1.4 client cannot install a host on a Windows machine over SSH.

## Verification

The installed Linux candidate passed 40 checks in two disposable Ubuntu containers using real Electron windows, real SSH and a simulated provider. The same standalone process survived local close/reopen and SSH takeover during work. Exactly one attempt persisted and finished while both clients were closed. The installed archive matched its manifest, no separate host cache was populated, and collected tokens were absent from captured logs and final UI. Containers were removed afterwards.

Focused lifecycle, transport, ownership and boundary tests passed, including concurrent startup and restarted-host discovery. Eighteen packaging integrity tests passed. The application builds, and independent static reviews found no remaining blocking issue in the examined lifecycle and ownership paths.

This does not establish real-provider performance, Windows support or Niclas's demonstration acceptance. The installed candidate trial preceded the clean tagged GitHub build; release artifacts are built from the tagged commit.
