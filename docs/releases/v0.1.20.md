# DSpatch 0.1.20

A Linux-only pre-release with a traced follow-up of Essentials in a whole generated walk (DSP-195, after DSP-192 and DSP-194). No Windows installer or Windows host package is published; the Windows work (DSP-182) is still open.

## Essentials in a whole walk (DSP-195)

- **What was found.** A walk generated in Essentials with Claude (`claude-opus-5-5`) read much like Standard before *Show more*: the change from launch to attach, a numbered order of what VS Code does, settings that later steps treat. With Copilot (`gpt-6-luna`) every profile was already short. Beside the profile, the walk's own preparation still sent a reader and a content list of its own to every profile: the shared task, the walk writer's role, the general writing rules (what happens and why, cause and effect, the names explained) and the one-call answer format's description of `body` and `why`. The loop reviewer's check named the same list. The reviewer did not ask for detail back in the runs made, and the walk structure and saved state were not the cause.
- **The change, instruction version 10.** With a profile, the writing rules give the form only, the shared task names what an explanation may cover and leaves the choice and the level to the profile, the one-call answer format describes its fields without a content list, and the reviewer checks each place at the reader's level. No brevity rule, length or identifier limit was added; code access, the walk context, Standard's mechanism and Teacher's concepts are kept. The reference `docs/CODE_WALK_UNDERSTANDING_AND_PROFILES.md` is unchanged at version 1.2: it already says that what reaches the agent outside the profile must not act as its content list.
- **The Step view.** *Why it matters* is part of the text you read first, so it now stands before the *Show more* control instead of after it.
- **What it gives, so far.** With Claude, the visible text of the observed step became somewhat shorter and no longer carried the numbered walk-through in the samples made, but Essentials still stays closer to Standard than the reference's calibration example. That remaining distance is the model's own selection under the Essentials reader. It is left for your judgment rather than forced with a brevity rule. With Copilot the texts stay short. Your own reading decides.

Walks and explanations saved by earlier versions are kept as they are and not regenerated; they carry the *earlier version of the instructions* notice from 0.1.15. Everything of 0.1.19 stands.

## Install or upgrade

Install `dspatch_0.1.20_amd64.deb` on Debian or Ubuntu x64 (`sudo apt install ./dspatch_0.1.20_amd64.deb`). Installing over an earlier version keeps `~/.config/DSpatch`.

0.1.20 changes no host method, so its host contract is the one 0.1.15 to 0.1.19 share. A host that one of those versions started and that a closed window left running is kept: at start DSpatch offers **Restart host**; press it before preparing walks or switching profiles, since the host builds the instructions. A host that 0.1.14 or earlier started cannot serve this window: at start DSpatch asks **Stop it and continue** or **Quit DSpatch**.

`dspatch-host-0.1.20-<commit>-linux-x64.tar.gz`, `host-manifest.json` and `SHA256SUMS` are published with this release.
