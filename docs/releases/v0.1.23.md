# DSpatch 0.1.23

A Linux-only pre-release. A walk's *Accept* now decides about exactly the lines its place marks (DSP-201), and the walk window's view preferences save again (DSP-200). It also adds *Help > About DSpatch*. No Windows installer or Windows host package is published; the Windows work (DSP-182) is still open. The colour and animation fixes come separately in a later release.

## A walk's Accept covers only the place's marked lines (DSP-201)

- **New decisions.** *Accept*, *Exempt* and *Withdraw* in a walk decide about exactly the changed lines of the place's marking: the lines the walk draws for that place. Before this, they covered the whole hunk around the place. In a new file that is the whole file: a place marking lines 151–159 of a new 417-line file accepted all 417 lines; it now accepts 9.
- **What never widens a decision:**
  - *Show more* context, *Whole file* or scrolling;
  - other places of the step, references and callers;
  - unchanged lines inside the marking, which are never counted.

  A place at To decides about its new lines and one at From about its old lines, so a place at To never takes removed lines of its hunk with it.
- **The Review section names the lines.** It says which lines are marked ("Marked here: new lines 151–159 in big.js (9 changed lines)"). The buttons and the confirmation name the same lines, and they are the lines saved. A step with several places marked together gets one decision per place.
- **The diff window and the file list follow line by line.** In the example the file reads 2%, "9 of 417 changed lines handled". A decision made in a walk says so on hover ("in walk step W1.1").
- **Withdraw** clears only the place's own lines. Decisions on other lines, including the diff window's, stay.
- **Walked through is unchanged.** *Mark this step walked through* is still a progress mark that approves no code.

**Older decisions are not corrected automatically.**
- **What they look like.** Decisions recorded with 0.1.22 or earlier may be wider than you meant: a walk's *Accept* then covered its whole hunk. They are kept and counted as recorded, so earlier coverage figures do not change and may overstate what you meant to accept.
- **Why they cannot be fixed for you.** Such a decision looks the same as one made in the diff window over the same lines, so what it was meant for cannot be known. DSpatch does not narrow it for you.
- **What the walk offers.** Where an earlier decision reaches beyond a place's marking, the walk says so, with how many lines it holds beyond the marking. You choose:
  - **Keep it as recorded**;
  - **Withdraw it**, after which the place can decide about its own lines again.

  Both act only on lines where that earlier decision still holds.

## The walk window's view preferences save again (DSP-200)

- **The fault.** In 0.1.22 the walk window could fail to save its language and column widths with "Not saved … Reason: Unknown preference value." This happened over preferences that an older DSpatch had saved, because the check depended on the order of the fields.
- **The fix.** The check now reads field by field, so field order no longer matters. Unknown fields and invalid values are still refused, and the other stored preferences are kept.
- **A clearer message.** If saving fails, the window now says that its language and column widths could not be saved and that the review is not affected.

## About DSpatch

*Help > About DSpatch* shows:
- the installed version and commit;
- the running host's own version, or *not known* when no host has reported one.

*Copy version information* puts both on the clipboard. The start window's title carries the version, for example *DSpatch — 0.1.23*.

## Install or upgrade

Install `dspatch_0.1.23_amd64.deb` on Debian or Ubuntu x64:

```bash
sudo apt install ./dspatch_0.1.23_amd64.deb
```

Installing over an earlier version keeps `~/.config/DSpatch`.

0.1.23 changes no host method, so its host contract is the one 0.1.15 to 0.1.22 share. A host that one of those versions started, and that a closed window left running, is kept: at start DSpatch offers **Restart host**. Press it before you use the review. The host records where a walk decision was made, and an older host drops that origin from new walk decisions. The exact lines themselves are saved correctly even before the restart, and so are the walk window's preferences: this window sends them in an order an older host accepts.

A host that 0.1.14 or earlier started cannot serve this window: at start DSpatch asks **Stop it and continue** or **Quit DSpatch**.

`dspatch-host-0.1.23-<commit>-linux-x64.tar.gz`, `host-manifest.json` and `SHA256SUMS` are published with this release.

## Verification

Checked before publication; details are in DSP-200, DSP-201, `docs/evaluations/dsp-200/` and `docs/evaluations/dsp-201/`:

- **Tests.** Type checks and the build pass. Targeted tests cover:
  - the 417-line case;
  - two and overlapping places;
  - context, removed and mixed changes;
  - older decisions;
  - preference key order, refusal and preservation.

  The review group passes on Linux CI.
- **Window trials on Linux under Xvfb:**
  - the Accept scope trial: 151–159 gives 9 of 417 accepted lines in the walk, the saved mark and the diff window, also after reopening the walk and after restarting the app and its host;
  - the view preference trial;
  - About and *Copy version information*.
- **Window trials on Windows:** the same Accept trial and preference trial.

Not established: other distributions than Ubuntu and Debian, arm64, and Windows packages.
