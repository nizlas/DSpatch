A test build. Not a finished release.

**Install on Ubuntu or Debian x64:** download `dspatch_0.1.1-rc.1_amd64.deb`, then install it with `sudo apt install` and the file's full path. On Windows x64: `DSpatch-Setup-0.1.1-rc.1.exe`. Check a download against `SHA256SUMS`.

**Work on another machine:** Remote Session, then `user@machine`. DSpatch fetches the matching host package from this release, checks its SHA-256 and installs it over SSH. No clone, Node, npm, copied package or tunnel is needed, and the remote machine does not need to reach GitHub for the host. It does need to reach the npm registry to fetch a provider's support. An SSH server and `tar` must be there already.

**Tried, on Linux x64 in clean containers:**
- Installing the .deb, and connecting over real SSH to a machine with neither Node nor DSpatch.
- Fetching the host package, a failed download and connecting again.
- Getting Claude and Copilot ready, Repair, and the vendors' real sign-in programs against local stand-ins.
- An answer using DSpatch's tool through the real Claude program, and a Copilot turn with a simulated provider.

**Not tried:**
- **Windows has not been run.** The installer and the Windows host package are built, nothing more.
- Real models and real accounts. The .deb on a real Ubuntu desktop under AppArmor.
- A remote Linux machine with no keychain cannot keep a Copilot sign-in. DSpatch says so.

**Content exclusion is partial.** Copilot's tool hooks run on the machine where the work runs, and they cover tool calls only. Prompt content, whole-folder searches and indirect commands are known gaps, listed in the [content-exclusion contract](https://github.com/nizlas/DSpatch/blob/main/docs/DSPATCH_CONTENT_EXCLUSION_CONTRACT.md).
