# DSpatch 0.1.10

A pre-release: the first Windows installer, with the Linux package built from the same commit.

## Windows installer (DSP-182)

- `DSpatch-Setup-0.1.10.exe` installs DSpatch for your user without administrator rights: a folder page (`%LOCALAPPDATA%\Programs\DSpatch` by default), a Shortcuts page with a Start menu entry always and a desktop shortcut only if you tick it, and a finish page that offers to start DSpatch. Apps and features lists *DSpatch 0.1.10*.
- The installer carries the Windows Copilot runtime and both host packages: the Windows one for local work, the Linux one for connecting to a Linux machine over SSH.
- The installer is not signed. Windows warns about it: the attachment manager's *Open File - Security Warning* for a downloaded file, and SmartScreen's *Windows protected your PC* page is what Microsoft documents next (*More info*, *Run anyway*). Browsers may hold the download, and a security product may do more: on one machine Bitdefender blocked the uninstaller file, which the wizard shows as *Error opening file for writing … Uninstall DSpatch.exe*; *Ignore* finishes the installation without an uninstaller. [INSTALL.md](../INSTALL.md#windows) says what to expect and how to remove DSpatch by hand.
- Installing a newer version over an older one keeps `%APPDATA%\DSpatch`: conversations, reviews, provider support and settings. The uninstaller removes the program and its shortcuts and keeps that data; it was not run to completion in this release's trials.
- Building on Windows: Git for Windows' tar read a drive letter as a remote host, so the host package build and the client's extraction of the bundled host now use Windows' own tar.

## Linux download

Install `dspatch_0.1.10_amd64.deb` on Debian or Ubuntu x64. Both host archives, `host-manifest.json` and `SHA256SUMS` are published with this release.

## Verification

Shown before publication on a Windows 11 Home machine, with isolated folders and the simulated provider (`app/scripts/install-trial.mjs`): the silent install into a chosen folder with the Windows runtimes bundled, the Start menu entry, the uninstall entry, an upgrade from 0.1.9 with the data byte for byte intact, and removal by hand; in real windows, the download warning, the wizard's folder and Shortcuts pages, and the file-write dialog with Bitdefender. On GitHub's Windows runner: the installer built with both host packages, an upgrade build, the download warning and the wizard's first pages. The Linux package passes the workflow's installed-package standalone trial before anything is published.

Not established in this release:

- The finish page, the first start of the installed client, the host through an upgrade and an uninstall, and the dock, zoom and profile trials against the installed client, in a completed automated run: the Windows runner's run still failed on the trial's own driver when this was tagged. The result goes to DSP-182.
- A real Copilot or Claude sign-in on Windows from the installed client, which needs the person's own account.
- What security products other than Bitdefender do with the unsigned installer and uninstaller.
- Real-provider pedagogical quality (simulated provider only).
