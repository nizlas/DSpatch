# DSpatch 0.1.8

## Review threads with recommendations

- A delegated review's findings, questions and verification gaps are now **threads** at their code in the diff. Each says what was observed, what it rests on, a recommended action with its reason and what is still uncertain. You can comment, ask the agent inside the thread, fold it to one line, or decide: *Accept recommendation*, *Keep open*, *Mark resolved*, *Dismiss* (with a reason) and *Reopen*. Accepting starts nothing: a recommendation that needs work reads *Action agreed* and stays among what remains.
- The same threads are reachable from code walks: Step lists the threads at the place shown, and choosing one shows its code with its lines marked. A place the agent named that does not exist says so and marks nothing.
- Points *Worth checking* are threads in the same flow; one that repeats a finding is that finding's thread.
- The review result shows coverage ("20/21 changed lines reviewed and approved by the agent") apart from what remains ("1 open question · 2 verification gaps"). Decisions on threads never approve lines.

## Ask, following answers and the walk's marks

- *Ask…* sits beside *Explain this* for code in walks, for explanation text and for answers; the selection is quoted in the question field with where it came from, and nothing is sent until you send it. Text selected in a thread is asked about in that thread.
- New questions come into view; a streaming answer is followed only while you are at the bottom. Scroll up and you stay where you are, with *New response ↓* to go back. Switching between Step and Discussion keeps your place.
- In a walk, only the active place is marked, on its own side's lines, with its repository, side and commit, file and lines in the pane's heading. The old and new lines of one change share one pane headed *Before*, *After* or *Before → After*. The first and last panes activate when you pan to the map's ends.
- The docked panel no longer goes blank when *Explain this* or a point shows it again.

## The workspace's other repositories as read context

- Reviews, walks and questions may read other Git repositories found under the workspace's folders, read-only and from Git at a recorded commit: a submodule pin or a declared version when that is established, otherwise HEAD, said as such. Citations name repository, file, lines and commit and open from the answer. Context code never counts as reviewed or approved.
- A walk step can show such library code as a **Context** place. It is shown in the step's explanation (Step), not yet as a stop of its own on the walk's code map.

## Presentation profiles

- A choice in the review panel, *Explanations*: **Original** (the walk's prepared explanation, as before, and the default), **Essens** (what changes, why, and what to understand or check; *Show more* gives the mechanism, special cases and more references) and **Pedagog** (a simple mental model first, with a short example; *Show more* adds detail in the same plain words). *What it asks for* shows exactly what the agent is told.
- Choosing a profile asks for the current step only; the prepared explanation stays shown meanwhile and is one click away after. A step you move to later offers its explanation with a button: nothing is generated by navigating. What was generated is kept and shown again without asking the agent, also after a restart. A profile changes the presentation, not the review: facts, findings, coverage and approval are the same.
- How well a real provider explains in each profile has not yet been judged; the instructions are one readable set (`app/src/shared/presentation-profiles.ts`) meant to be tried and adjusted.

## Explain more simply, and follow-up questions

- *Explain more simply* now aims for fewer concepts at once, starts with what the code achieves, keeps caveats and does not grow longer. Pressed again, it is given the explanations already shown and asked for another way in, and finally for one short question about what is unclear instead of "it cannot be simpler".
- A follow-up question is answered at the level of the explanation it follows, in the profile you read in.

## Linux download

Install `dspatch_0.1.8_amd64.deb` on Debian or Ubuntu x64. No separate Node, npm or host-package installation is required. The matching standalone host archive, its manifest and `SHA256SUMS` are also published. No Windows installer and no Windows host package are in this release.

**Upgrading from 0.1.7 or earlier.** This release changes what the window and its host say to each other, so it cannot use a host an earlier version left running. On first start it says so before any window opens — *Another DSpatch host is running here* — and offers **Stop it and continue**, which ends the older host (and any work still running there, whose outcome is then unknown) and starts this version's. Conversations, reviews, walks, threads and zoom levels are kept. For later updates that keep the same host contract, the status line reads *Restart needed to finish updating* with a **Restart host** button instead.

On GitHub's Ubuntu runners, `linux-verify` at f6104c1 (the release's code; the release commit adds these notes and trial changes) passed (run 42123823468): the fast (1582 pass, 6 skipped), host (144 pass, 3 skipped), review (257), chat (362 pass, 7 skipped), presentation (311), provider (170), loop (674) and live (116 pass, 6 skipped) test groups, the zoom trial (78 checks), the dock trial (54) and the governor (27).

The .deb built locally from f6104c1 (client, host package and manifest all naming that commit), unpacked and started under Xvfb on Linux with a simulated provider: the presentation-profile trial 59 checks, the review-thread trial passed (threads, recommendations and decisions, Ask, following streaming answers docked and standalone, the walk's focus marks over time, Worth checking as threads, context places and citations), the dock trial 54 checks. In a clean Ubuntu container: 0.1.7 used (a conversation, a review with the agent's delegated result, zoom levels, a loop of the person's own), 0.1.8 installed over it while 0.1.7's host was still running; the new client found that host and asked before stopping it; after *Stop it and continue* this release's host took over, and the conversation, the review and its result, the zoom of the chat and review windows and the loop were all as before, also after a restart (27 checks). The staged release check confirmed the .deb against `SHA256SUMS` and that Connect over SSH installs the host the client carries with github.com unreachable; its later part stopped at its restart of the client, as for 0.1.7, and is covered by the check of the published release.

Not established: what a real provider makes of the presentation profiles and the new Explain more simply (simulated answers show the window and the data flow, not the quality of the explanations); a physical mouse and keyboard; a real desktop session; Windows.
