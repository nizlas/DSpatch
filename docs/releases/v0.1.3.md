# DSpatch 0.1.3

## Fixes and improvements

- An idle host with a ready loop drawing can hand over to a remote connection.
- Remote Connect starts an installed host with a compatible protocol and contract without requiring a host-package manifest on the client.
- Graph terminals can declare `report-delivered`, keeping report delivery separate from code verification. Success terminals retain their evidence freshness requirements.
- The terminal inspector exposes Report delivered, and stored history preserves that meaning. Required reports and cancellation guards remain enforced.
- DSpatch's runnable development loop declares report delivery explicitly. Project graphs require an explicit choice; historical runs are not reclassified.

## Downloads

Install `dspatch_0.1.3_amd64.deb` on Debian or Ubuntu x64. Matching Linux and Windows standalone host packages, their manifest and `SHA256SUMS` are included.

This release does not include a Windows desktop installer. The v0.1.2 Linux build succeeded, but its Windows installer job failed and prevented publication. Linux publication is independent of that manual Windows build in this release; the existing v0.1.2 tag is retained without rewriting it.

## Verification and limits

The focused loop, history, evidence, serialization and SSH regressions pass, as do the host and renderer typechecks. The report-ending change received independent read-only review without correctness findings. Actual-window assessment, Windows execution and a complete packaged two-machine trial remain outstanding. Building an artifact does not establish those checks.
