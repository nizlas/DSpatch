# DSpatch 1.0.3

A pre-release for **Linux x64** and **Windows x64** that makes the Windows-host guide three steps. 1.0.0 stays the latest ordinary release.

## Help: three steps, the rest behind links

- *Help → Connect to a Windows Host over SSH…* now opens on three steps and nothing else: on Linux, run the helper; on Windows, run the command it prints, in PowerShell as administrator; on Linux, check the fingerprint with `ssh` and connect with **Remote Session**. Opening PowerShell as administrator is described at step 2, and the fingerprint check at step 3.
- Troubleshooting, other ways to run the scripts, manual setup, how it works, and what has been tested are separate views, opened by links below the steps, each with a link back. **Save Windows script…** and **Save Linux helper…** are in *Other ways to run the scripts*, for a Windows computer that cannot download from GitHub.
- Commands in Help wrap instead of scrolling, and never run under their Copy button.

## The Linux helper prints one ready command

- Installed with DSpatch, `dspatch-prepare-linux-client.sh <windows-user>@<windows-host>` prints a single line to paste into PowerShell as administrator. That line downloads this version's `dspatch-prepare-windows-host.ps1` from the release page and runs it only if its SHA-256 is that of the script installed with DSpatch. The public key, this computer's address and the Windows user are filled in. Nothing has to be carried over, unpacked or assembled except that line.
- The helper also saves the line in `~/dspatch-windows-command.txt`, and says what to do next on Windows and then on Linux.
- A copy of the helper saved elsewhere, without the release beside it, prints the command for a Windows script saved by hand.

The Windows script and the host contract are unchanged from 1.0.2.

## Install

- **Linux (Debian/Ubuntu x64):** `dspatch_1.0.3_amd64.deb`. Check it against `SHA256SUMS` and install with `sudo apt install ./dspatch_1.0.3_amd64.deb`.
- **Windows (x64):** `DSpatch-Setup-1.0.3.exe`, a per-user installer. It is not signed; see [INSTALL.md](../INSTALL.md#windows).
- `dspatch-prepare-windows-host.ps1`, `dspatch-prepare-linux-client.sh`, both host packages, `host-manifest.json` and `SHA256SUMS` are published with this release.

## Tried, and still to be tried

Tried by agents:

- The Help window in this checkout's build, opened from its menu item, with an isolated profile: the three steps fit a 900×900 window. Every view opens from its link and returns. The two save buttons save files identical to the scripts. The native save dialog was answered by the trial, not shown.
- The Linux helper in a temporary home folder, both installed (with the release beside it) and as a saved copy.
- On a real Windows 11 computer, read-only: the printed command, with a throwaway key and `-DryRun` added, downloaded 1.0.2's Windows script, which is the same file, found its SHA-256 as expected, ran it and showed the plan. Nothing was changed: no rule and no key were added, and the downloaded file was removed.

Not yet tried:

- **the Windows script's system-changing path** (installing OpenSSH, creating the firewall rule, writing a key, setting permissions, starting sshd) **has not been run on any Windows computer**;
- the whole three-step flow with this release's packages, from a new Linux computer to Connect;
- the Help window on a real screen, and the native save dialog;
- a work network with its own policies, and Copilot on such a host;
- the open points listed for 1.0.1 and 1.0.2.
