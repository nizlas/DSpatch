The first release that is not a prerelease. DSpatch is under active development; the limits below matter.

**Install on Ubuntu or Debian x64:** download `dspatch_0.1.1_amd64.deb`, then install it with `sudo apt install` and the file's full path. On Windows x64: `DSpatch-Setup-0.1.1.exe`. Check a download against `SHA256SUMS`.

**Work on another machine:** Remote Session, then `user@machine` or an SSH alias. DSpatch fetches the matching host package from this release, checks its SHA-256 and installs it over SSH. No clone, Node, npm, copied package or tunnel is needed. An SSH server and `tar` must be there already, and that machine must reach the npm registry to fetch a provider's support.

**New in this release:**
- **One work context per computer.** Start locally, connect to the same account from a laptop, and continue with the same projects, conversations, reviews and loop runs; come back later. One client works at a time, a window left open hands over unless work runs in it, and a running job is followed, never sent again. See [the installation guide](https://github.com/nizlas/DSpatch/blob/v0.1.1/docs/INSTALL.md#for-a-person-using-dspatch).
- **Upgrading from a prerelease.** A host's older data folder is backed up and brought in without overwriting anything. A saved manual tunnel that no longer answers leads to Connect over SSH.
- **Delegated review** shows real activity while it runs, and its result starts with what was approved and what remains, with findings set apart and details folded.
- **The larger loop is the default** when none was chosen. Simple chat loop stays an option, and a copy of a shipped loop no longer appears twice.
- **SSH aliases** work with blocks written for a terminal, and a refused sign-in shows the user, host and port ssh actually used.

**Tried, on Linux x64 with the packages of this release, in clean containers with a simulated provider:** installing the .deb without Node or sources, the real download of the host package, real SSH with aliases, local → remote → local and remote → local, handing over, following a running job, adopting a real earlier host's folder, a saved tunnel that is gone, provider preparation and sign-in programs against local stand-ins, and Copilot hooks on the right host.

**Reported by a user on an earlier build, not a full check:** release installation, SSH connection and real Copilot, with a real pre-tool hook blocking a file read.

**Not tried:**
- **Windows has not been run.** The installer and the Windows host package are built. The PowerShell steps were parsed, and Windows paths are unit-tested; no Windows machine ran any of it. On Windows a replaced host is ended, not closed in order.
- **Moving between two real computers** has not been done: the local and remote paths were tried in containers.
- Real models and real accounts in these trials. The .deb on a real Ubuntu desktop under AppArmor for the new flows.
- A Linux machine with no keychain cannot keep a Copilot sign-in. DSpatch says so.
- How well real models fill the new structure of a delegated review. A result without it falls back to the older form.

**Content exclusion is partial.** Copilot's tool hooks run on the machine where the work runs and cover tool calls only. Prompt content, whole-folder searches and indirect commands are known gaps, listed in the [content-exclusion contract](https://github.com/nizlas/DSpatch/blob/v0.1.1/docs/DSPATCH_CONTENT_EXCLUSION_CONTRACT.md).
