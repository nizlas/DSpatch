# DSpatch 0.1.2

*Not published. The tag `v0.1.2` exists, but its Windows desktop packaging failed and publication was skipped, so no file below was released; v0.1.3 carries these changes. Corrected 3 November 2026 (DSP-164).*

## Fixes and improvements

- A ready loop drawing does not make an idle host report that a loop is running.
- Remote Connect starts an installed compatible host without requiring a host-package manifest on the client. An exact build is preferred; protocol and contract compatibility remain mandatory.
- Graph terminals can explicitly declare `report-delivered`. A final report written after the last command can be delivered without certifying the code. Success terminals retain their verification freshness requirements.
- The terminal inspector exposes Report delivered, and stored conversation history distinguishes delivery from verification. Missing required reports and cancelled runs do not count as delivered.
- The runnable DSpatch development loop uses the report-delivery ending. Existing project graphs need an explicit terminal choice; historical runs are not reclassified.

## Verification and limits

The focused loop, history, evidence, graph serialization and SSH regression tests pass, as do the Node and renderer typechecks. The report-ending implementation received an independent read-only review without correctness findings.

Actual-window assessment of the terminal selector and report-history presentation remains outstanding. The Windows bootstrap change and installer have not been exercised on a Windows machine. Building the installers is not evidence that these manual checks passed.
