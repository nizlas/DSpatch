# DSpatch 1.0.1

A pre-release for **Linux x64** and **Windows x64**, made so that DSpatch on a Linux computer can work on a Windows computer over SSH. 1.0.0 stays the latest ordinary release.

## Working on a Windows computer from Linux

- **Connect to a Windows host works.** The host package that a Linux client sends to Windows now goes over SFTP, on the same SSH connection, config and sign-in as the other steps (DSP-211). Before, it went to Windows PowerShell on its standard input, which took the first 4 KB and then almost nothing, so Connect stood at *Installing host 0 %*. The package is still checked against its SHA-256 on Windows before it is unpacked beside earlier versions and put in place.
- **Cancel stops a Connect.** While connecting, Cancel now ends the attempt and its own `ssh` and `sftp` processes, and the dialog says so. Before, it only closed the dialog.
- **A guide under Help.** *Help → Connect to a Windows Host over SSH…* explains the whole setup for a Linux client and a Windows host on one internal network: OpenSSH Server, a narrow firewall rule, key sign-in for standard and administrator accounts, checking the host key, the first Connect, and troubleshooting. Commands have a Copy button.
- **The first provider setup on such a host.** A host that DSpatch installed keeps its provider support in `%APPDATA%\DSpatch\provider-support` and may ask to set a provider up once, even if it already worked when DSpatch ran from a development checkout.

Everything else is DSpatch as of commit 7c2e237 on main, which includes the work since 1.0.0 (the loop editor's Run and Edit modes, step output windows and more).

## Install

- **Linux (Debian/Ubuntu x64):** `dspatch_1.0.1_amd64.deb`. Check it against `SHA256SUMS` and install with `sudo apt install ./dspatch_1.0.1_amd64.deb`. It carries both host packages, so it can install a host on a Linux or a Windows computer.
- **Windows (x64):** `DSpatch-Setup-1.0.1.exe`, a per-user installer. It is not signed, so Windows and security products warn about it; see [INSTALL.md](../INSTALL.md#windows). For working on a Windows computer from Linux, the Windows app is not needed: the Linux client installs its own host there.
- `dspatch-host-1.0.1-<commit>-linux-x64.tar.gz`, `…-win32-x64.tar.gz`, `host-manifest.json` and `SHA256SUMS` are published with this release.

A host started by an earlier version keeps running; 1.0.1 has the same host contract as 7c2e237, so the window or the Connect dialog offers to restart or replace it, and answering No keeps using it.

## Shown, and still to be tried by hand

Shown on 15 November 2026 from a Linux client to a Windows 11 computer on a home network, with key sign-in, using a build of the SFTP change: the host package sent, checked, installed and started on Windows, the tunnel opened, the Windows computer's projects shown, and the first Claude setup for that host. The real 107 MB transfer was also checked on Windows by size and SHA-256. Targeted tests cover the transfer step, the SFTP arguments, a failed transfer and Cancel ending a transfer in progress.

Not yet shown:

- reconnecting after the client or the connection is interrupted, and going on with work after that;
- Cancel in a real window;
- the setup on a work network with its own policies, and Copilot on such a host;
- a Windows client connecting to a Windows host;
- the Windows installer's open points from DSP-182 (the uninstaller under Bitdefender, the window trials on Windows).
