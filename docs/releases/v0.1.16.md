# DSpatch 0.1.16

A Linux-only pre-release that makes the walk loop's run view a readable live stream (DSP-191), for Niclas's demo. No Windows installer or Windows host package is published; the Windows work (DSP-182) is still open.

## Code walk generation, followed (DSP-191)

- **Left: the heading, the liveness line, the loop.** *Code walk generation*, then one line with what the agent is doing now in the words the job itself reports (the same spinner and sentences the diff window's job line shows: planning, writing step 3 of 8, reading a file, the reviewer's final assessment), then the animated loop as in 0.1.15. The internal line of provider, model, profile, version and graph is gone.
- **The live stream, beside the graph.** A click on the liveness line opens it; a click again, or Close, closes it, and the run goes on; the line keeps updating while it is closed. One chronological flow with one scroll: discreet dividers for the role and the turn, the agent's exposed reasoning and reply text open and growing as fragments arrive, short lines for tool activity (reading a file, searching), commands readable with large results collapsed, the reviewer's assessment and findings, and a plain sentence for a turn that failed. Nothing is invented: a quiet turn shows nothing.
- **Scrolling.** The stream follows its foot from the start; scrolling up stops following and the reader's place stays while text arrives; scrolling back to the foot resumes it; opening a collapsed result moves nothing.
- **No debug information in the view**, by Niclas's explicit decision: no token events, cache values, internal states, graph ids, instruction versions, raw events, prompts or protocol dumps, and none of it behind any control. *Every prompt and answer of the run* is gone from the view. All of that stays in the run's files beside the review (`record.jsonl`, `activity.jsonl`, `summary.json`, `graph.json`) for troubleshooting and for agents.
- **The record during a run.** *That preparation has no loop record* while the run was going came from the record call requiring the job's summary, which is written with the end; the record is now served from its place from the first turn. The stream itself never depended on it: it reads the run through the live snapshot and the numbered events, and a window opened or reopened during the run gets the state so far once and only later events after that, with nothing doubled or lost.
- **Older runs.** A run recorded by 0.1.14 shows its answers and says in one sentence that the live text, the reasoning and the tool activity were not kept for it.

Everything decided in 0.1.15 stands: the diff view keeps one line about the preparation, the reading profile is the person's and never a reason to prepare again, Stop is the job's own, closing a window stops nothing.

## Install or upgrade

Install `dspatch_0.1.16_amd64.deb` on Debian or Ubuntu x64 (`sudo apt install ./dspatch_0.1.16_amd64.deb`). Installing over an earlier version keeps `~/.config/DSpatch`.

0.1.16 changes no host method, so its host contract is 0.1.15's. A host that 0.1.15 started and that a closed window left running is kept: at start DSpatch says a restart is needed to finish updating and offers **Restart host**; press it before preparing walks, since walks are prepared on the host. A host that 0.1.14 or earlier started cannot serve this window: at start DSpatch asks **Stop it and continue** or **Quit DSpatch**, and this release's host then starts.

`dspatch-host-0.1.16-<commit>-linux-x64.tar.gz`, `host-manifest.json` and `SHA256SUMS` are published with this release.

## Verification

Checked before publication (details in DSP-191): type checks and the build; the follow preparation trial in real windows with the simulated provider (the stream opened from the liveness line during a run with text growing and no entry to open, scrolling up kept and resumed, the stream and the window closed and reopened without a stop, a double or an extra call, the role dividers, the correction round, the end, no debug or token text in the view, the finished run from its files, the profile switch, a second review stopped from its view, a provider failure, a review deleted while its loop ran); the loop trial's diff-line stage; the follow state's unit tests.

Not established: anything with a real provider (what Claude, Copilot or Cursor stream in a walk loop has not been seen in this view with a real model); `linux-verify` and the published-package trial, which run after this release is published for the demo and are reported in the task; Windows, other distributions than Ubuntu and Debian, and arm64.
